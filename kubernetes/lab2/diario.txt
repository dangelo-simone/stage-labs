ILM sposta indici di log vecchi (cold/frozen) su storage più economici (perché ci si accede meno spesso) e tramite rollover (size o età) vengono creati nuovi indici
non avendo più di un hardware dove immagazzinare gli indici di ogni "temperatura"

steps:
policy
template per applicare le policy agli index 
non uso data streams (da quello che leggo data streams sono meglio e più moderne, astraggono parte di questo processo di policy, template, etc + hanno anche ottimizzazioni varie, etc. ref: https://discuss.elastic.co/t/datastream-over-index-with-ilm/350078), ma rolling indices: devo creare un indice e alias iniziale già gestito
logstash che scrive sull'indice


nella console dev di kibana:
policy: in hot rollover appena l'indice tocca 5 documenti o 5 minuti, dopo 2 minuti dal rollover passa in warm e fa forcemerge 10 minuti dopo il rollover fa delete. I min_age si contano dal momento del rollover. Ho messo set_priority

PUT _ilm/policy/wordpress-logs-policy
{
  "policy": {
    "phases": {
      "hot": {
        "actions": {
          "rollover": { "max_docs": 5, "max_age": "5m" },
          "set_priority": { "priority": 100 }
        }
      },
      "warm": {
        "min_age": "2m",
        "actions": {
          "forcemerge": { "max_num_segments": 1 },
          "set_priority": { "priority": 50 }
        }
      },
      "delete": {
        "min_age": "10m",
        "actions": { "delete": {} }
      }
    }
  }
}

template:
PUT _index_template/wordpress-logs-template
{
  "index_patterns": ["wordpress-logs-*"],
  "template": {
    "settings": {
      "number_of_replicas": 0,
      "index.lifecycle.name": "wordpress-logs-policy",
      "index.lifecycle.rollover_alias": "wordpress-logs"
    }
  }
}
